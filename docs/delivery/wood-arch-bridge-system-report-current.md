# 1 项目与系统概述

## 1.1 建设目标

中国木拱廊桥智能设计系统面向木拱廊桥研究、参数化方案设计和成果复核场景。在当前版本中，用户可以通过自然语言或表单输入桥梁基本参数，完成参数归一化、方案估算、结构图纸生成、结果查看、安全与寿命筛选、候选方案比较、Excel 导出以及可选的 BIMFACE 三维模型查看。

系统的主要价值是把分散的设计参数、规则计算、结构表达和方案比较集中到一个可追溯的工作台中，缩短方案阶段的重复计算与信息整理时间。

## 1.2 当前使用对象

- 木拱廊桥研究与设计人员：录入或调整方案参数，查看构件建议和图纸。
- 成果复核人员：查看参数、结果、筛选指标及导出成果。
- 系统管理员和运维人员：维护账号、权限、菜单、基础数据和运行环境。
- 后续算法研发人员：使用标注、数据整理和试验训练工具继续完善节点几何模型。

## 1.3 当前已实现范围

| 能力域 | 当前状态 | 说明 |
|---|---|---|
| 用户、角色、菜单和权限 | 已具备 | 继承 Django-Vue3-Admin 的前后端分离 RBAC 基础能力 |
| 自然语言参数转换 | 已具备 | 采用本地确定性规则提取参数，不依赖本地大模型服务 |
| 参数化方案预测 | 已具备 | SSA-XGBoost 预测矢跨比，CF-BPNN 预测五类根径，并保留规则回退 |
| 结构图纸生成 | 已具备 | 服务端生成 PNG 工程表达图，前端支持缩放、复位和下载 |
| 结果查看与 Excel 导出 | 已具备 | 展示构件直径、构件长度、矢跨比和可信度等结果 |
| 安全筛选 | 已具备 | 提供可靠度代理、构件指标和腐朽风险提示，仅用于方案筛选 |

## 1.4 关键术语

| 术语 | 本报告中的含义 |
|---|---|
| 三节苗、五节苗 | 系统当前图纸和参数中使用的木拱构架组成类型 |
| n1、n2 | 三节苗和五节苗的离散数量参数 |
| 矢跨比 | 拱矢高与单孔净跨之比 |
| 可信度 | 当前输入适用域和输出检查形成的方案提示，不是统计学置信度或工程鉴定结论 |
| 右删失证据 | 构筑物已服役至当前年限且仍在役，用于更新寿命分布的信息 |
| 筛选模型 | 用于方案比较和风险提示的计算模型，不能直接作为最终工程结论 |

# 2 系统总体框架

## 2.1 总体逻辑架构

系统采用浏览器/服务器模式和前后端分离架构。浏览器端提供设计工作台与管理界面；Django 服务负责平台管理和业务基础能力；FastAPI 算法服务负责桥梁参数处理、图纸生成、筛选计算和成果导出；PostgreSQL 与 Redis 分别承担业务数据和缓存/消息基础设施；离线工具链承担标注、数据整理和试验训练。

```text
┌──────────────────────────────────────────────────────────────┐
│ 浏览器端：设计工作台、系统管理、权限菜单、结果展示与下载   │
└──────────────────────────┬───────────────────────────────────┘
                           │ HTTP/JSON、PNG、XLSX
                    ┌──────▼──────┐
                    │ Nginx 网关  │
                    └───┬─────┬───┘
                        │     │
              /api/     │     │ /bridge-api/
                ┌───────▼┐   ┌▼──────────────────────┐
                │ Django │   │ FastAPI 桥梁算法服务  │
                │ 业务层 │   │ 预测/绘图/分析/优化   │
                └───┬───┘   └──────────┬────────────┘
                    │                  │
           ┌────────▼──────┐    ┌──────▼──────────────┐
           │ PostgreSQL    │    │ BIMFACE（可选外部） │
           │ Redis         │    └─────────────────────┘
           └───────────────┘

离线研发链路：原图 → 八点标注 → 数据修复/对称目标 → 分组验证 → 试验模型
```

## 2.2 运行拓扑

| 服务 | 主要职责 | 容器内端口 | 对外方式 |
|---|---|---:|---|
| bridge-web | 前端静态资源、统一反向代理、媒体文件访问 | 6000 | 默认映射到主机 80 和 6000 |
| bridge-backend | Django 管理平台和业务接口 | 8002 | 由 Nginx `/api/` 代理 |
| bridge-algorithm | 桥梁算法、图纸、分析、导出和 BIMFACE 代理 | 8001 | 由 Nginx `/bridge-api/` 代理 |
| bridge-redis | 缓存与异步基础设施 | 6379 | 仅容器网络内部使用 |
| PostgreSQL | 业务数据库 | 由部署环境确定 | 当前 Compose 通过环境变量连接外部实例 |

各服务通过 `bridge-network` 容器网络通信。生产配置通过环境变量注入，报告不记录密码、令牌或平台密钥。

## 2.3 模块职责

### 2.3.1 前端应用

前端负责登录后的菜单导航、权限可见性、设计参数交互、当前浏览器会话内的工作状态保存、各结果页签展示以及文件下载。桥梁设计工作台使用同一份方案状态驱动“3D 模型、结构图纸、设计参数、预测结果、安全分析、优化设计”六个功能区。当前尚未实现桥梁方案的服务端永久存档和版本管理。

当前路由与页签采用双向同步：菜单路由变化会切换对应页签，页签变化也会更新路由。因此生成图纸后跳转到“结构图纸”时，左侧菜单会同步高亮结构图纸，不再停留在“3D 模型”。

### 2.3.2 Django 管理平台

Django 服务提供账号认证、JWT 会话、用户、角色、菜单、组织/部门和常用后台管理能力，并为前端动态路由和权限控制提供基础数据。桥梁算法计算未直接耦合到 Django 进程，而是由独立 FastAPI 服务承载，便于独立扩展和测试。

### 2.3.3 桥梁算法服务

算法服务提供参数提取与归一化、导师参数模型推理、五节苗节点 Pilot 推理、确定性骨架几何、图纸绘制、安全筛选、寿命估计、候选方案生成、Excel 导出、BIMFACE 访问令牌代理和节点标注工具入口。其核心接口见附录 A。

### 2.3.4 离线数据与模型工具

离线工具包括浏览器标注页面、标注 JSON 修复、对称目标构造、训练数据准备、分组交叉验证和试验模型训练。五节苗节点训练仍与在线服务隔离，只有审核后的双产物才可通过显式配置加载。

## 2.4 主要数据流

1. 用户用自然语言或表单提交长度、跨度、桥宽、孔数、n1、n2 和可选矢高。
2. 算法服务对参数进行提取、默认值补齐和范围归一化。
3. SSA-XGBoost 预测矢跨比，CF-BPNN 按原权重矩阵推理五类构件根径范围。
4. 五节苗节点 Pilot 预测 `alpha/beta`，随后按知识约束重建 `Q1—Q4` 并确定性计算三节苗、五节苗构件长度。
5. 前端将结果及模型来源保存在当前工作台状态中，并按操作跳转到参数、结果或图纸页面。
6. 图纸接口依据当前参数和节点几何比例生成 PNG；导出接口生成 Excel。
7. 安全分析和优化接口复用当前方案结果，返回筛选指标或候选排序。

## 3.2 前端实现

设计工作台采用 Vue 组合式 API 组织状态和动作，使用 Element Plus 实现表单、标签页、结果卡片、表格与提示。方案参数、分析条件和最近结果会写入浏览器本地状态，用于页面路由切换后的恢复。

前端通过统一 API 封装调用桥梁算法服务，响应类型对参数、预测结果、安全结果、优化结果和 BIMFACE 数据进行约束。工作台状态保存在浏览器 `sessionStorage` 中；刷新后参数和结构化结果可以恢复，但 PNG 图纸需要重新生成。当前工作台的菜单路径与页签映射集中维护，以减少功能区切换时的状态不同步。

## 3.3 后台管理实现

后台基于 Django-Vue3-Admin 的模块化结构，采用 Django REST Framework 暴露接口，通过 JWT 维持登录状态。菜单与路由由后台权限数据驱动，适合按甲方组织和岗位配置可见功能。数据库、跨域范围、主机名和 Redis 等均通过部署环境配置。

## 3.4 算法服务实现

算法服务独立部署，采用同步 HTTP 接口。不同能力按接口隔离：

- `/predict`：接收结构化参数并返回导师参数模型、节点 Pilot 和确定性骨架几何的组合结果；
- `/chat`：把自然语言转成结构化参数，并同时返回方案、结果和图纸；
- `/visualize`：生成当前方案的 PNG 图纸；
- `/analyze`：生成可靠度代理、腐朽风险和寿命筛选信息；
- `/optimize`：生成和比较候选方案；
- `/export/excel`：导出桥梁设计结果；
- `/bimface/*`：在服务端保管平台配置并代理模型访问；
- `/annotation`：提供节点几何标注工具。

算法服务不要求 Ollama 或其他本地大模型进程。自然语言到结构化参数的转换采用可复现规则路由；参数形成后与表单入口共用同一模型推理链。

## 3.5 节点几何与试验训练链路

当前图纸使用节点 Pilot 输出的五节苗几何比例；模型未启用、产物缺失、输入越界或预测非法时回退到 `alpha=2/3`、`beta=1/4`。研发链路已经能够：

1. 对每张原图标注 A、B、C、D、Q1、Q2、Q3、Q4 八个节点；
2. 保存和恢复 JSON，并校验原图文件名匹配；
3. 保留左右观测值，同时构造对称训练目标；
4. 按 `split_group_key` 分组，避免同一桥或同一测绘谱系跨训练/测试折；
5. 执行外层 Leave-One-Group-Out 和内层 GroupKFold 试验验证。

现有数据为 103 条完成预处理，其中 102 条标准结构记录、96 个隔离分组参与训练。v6 仍选择 Ridge：`alpha` 使用净跨，`beta` 使用净跨和矢跨比；产物标记为 `pilot_not_for_production`，已接入本地受控服务，生产环境默认关闭。

## 3.6 接口与文件格式

业务接口主要使用 JSON。图纸以 Base64 或 PNG 形式返回，Excel 以 XLSX 文件流返回。标注数据使用 JSON；训练准备结果使用 CSV/JSON 等便于审计的文件格式。接口异常通过 HTTP 状态码和错误信息向前端反馈。

# 4 已实现功能说明

## 4.1 登录与菜单

用户通过系统登录页进入平台。登录后，系统根据账号所属角色生成可访问菜单。桥梁设计相关功能以独立菜单路径呈现，同时在同一工作台中保持当前方案状态。

## 4.2 自然语言设计输入

用户可以输入包含总长、净跨、桥面宽度、孔数、三节苗数量、五节苗数量和矢高等内容的中文描述。系统使用关键词与数字规则提取参数，随后进行标准化并生成方案。

示例：

> 设计一座总长 54 米、单孔净跨 18 米、桥面宽 4.8 米的 3 孔木拱廊桥。

本功能不调用生成式模型，不产生开放式设计推理。未明确给出的字段会按系统默认值补齐，用户应在“设计参数”中复核后再使用结果。

## 4.3 设计参数

当前表单支持：

| 参数 | 当前输入范围/规则 |
|---|---|
| 桥梁总长 | 5～120 m |
| 单孔净跨 | 3～40 m |
| 桥面宽度 | 3～8 m |
| 孔数 | 1～6 |
| 三节苗数量 n1 | 5～11 |
| 五节苗数量 n2 | 4～10 |
| 矢高 | 可选；未填时按跨度计算默认值 |

用户修改参数后可重新执行预测。系统会对数值进行边界限制和标准化，以减少无效输入进入后续计算。

## 4.4 预测结果

结果页展示：

- 矢跨比和矢高；
- 三节苗平弦、斜弦的建议直径范围；
- 五节苗平弦、两类斜弦的建议直径范围；
- 主要构件长度估算；
- 适用域可信度分值、等级和方法标识；
- `alpha/beta`、当前节点几何来源、模型版本与算法阶段链；
- Excel 导出入口。

当前在线主链已加载从用户原始备份恢复的 SSA-XGBoost 与 CF-BPNN，并在本地受控环境连接 v6 五节苗节点 Pilot。接口响应会逐阶段返回来源和版本；任何阶段回退均明确标注原因，不把规则结果冒充模型输出。

## 4.5 结构图纸

系统根据当前参数绘制木拱廊桥工程表达图，包含侧立面、节点和参数标题等信息。用户可以：

- 首次进入图纸页时自动生成图纸；
- 通过滚轮或按钮缩放，缩放范围约为 0.6～2.0；
- 恢复 1:1 显示；
- 下载 PNG 文件；
- 修改参数后重新生成。

生成完成后，前端会切换到“结构图纸”路径，并同步菜单高亮。

## 4.6 安全分析

安全分析支持选择木材俗名、当前服役年限、暴露环境、维护水平和是否防腐处理。输出包括整体评分、可靠度代理、构件失效指标、易损部位、建议检查周期、腐朽风险和寿命估计。

所有结果均属于方案阶段筛选。系统没有替代现场检测、材料试验、荷载复核、节点承载力验算及正式鉴定流程。

## 4.7 贝叶斯寿命估计

寿命模块采用解析 Weibull–Gamma 贝叶斯生存模型，输出：

- 场景调整后的先验寿命；
- 预计总寿命中位数和均值；
- 90% 先验或后验预测区间；
- 预计剩余寿命及区间；
- 未来 10 年存续概率；
- 已使用证据、未使用因素和缺失因素。

当输入当前服役年限时，系统把“已服役至该年限且仍在役”作为右删失证据更新分布。当前先验中位数、暴露/维护/防腐情景因子和腐朽终点阈值尚未用本项目长期巡检数据标定，因此结果只能用于方案比较。

## 4.8 优化设计

系统围绕 n1、n2 和矢跨比生成若干候选组合，分别计算安全、经济性、拱形质量、冗余度和综合分值，并按综合分值排序。用户可以查看候选方案相对原方案的参数和指标变化，然后把选定方案回填到当前设计。

当前能力属于离散候选生成与启发式多目标评分，不是基于完整结构分析约束的数学优化，也不自动确认工程最优解。

## 4.9 三维模型

三维功能通过 BIMFACE 查看预先上传并配置的模型，不会根据当前参数实时生成三维桥梁。系统从算法服务获取 View Token，前端已具备构件点击、标注和属性面板框架；当前后端构件属性接口返回空属性数组，真实属性展示仍需 BIM 数据和接口补齐。该功能需要：

- 配置有效的 BIMFACE 应用密钥和文件编号；
- 算法服务能够访问 BIMFACE 网络；
- 指定文件已完成平台转换。

模型缺失或网络不可用时，不影响参数、图纸、结果、分析和导出等本地功能。

## 4.10 标注工具

节点标注工具面向研发人员，支持载入原图、八点标注、拖动修正、缩放、平移、标签隐藏、JSON 保存与恢复以及批量复核。多孔桥按单孔分别形成标注 JSON。恢复标注时必须校验 `source_image` 与当前原图文件名一致，防止错配。

# 5 算法与数据处理说明

## 5.1 规则化自然语言参数提取

系统通过关键词匹配识别总长、跨度、桥宽、孔数、n1、n2 和矢高，并对常见中文表达进行数值提取。提取后统一进入参数归一化函数，因此自然语言入口与表单入口共用同一计算链路。

该实现具备低依赖、可解释、可复现的特点。边界是目前不理解复杂上下文，也不使用对话历史补全含糊条件；用户应在参数页确认提取结果。

## 5.2 导师参数模型与兼容回退

第一阶段使用 SSA-XGBoost 预测矢跨比，第二阶段使用 CF-BPNN 原权重矩阵推理三节苗平弦/斜弦以及五节苗平弦/两类斜弦的根径范围。旧版模型已转换为 XGBoost 原生模型文件和 NumPy 数值权重包；在线服务校验清单与哈希后加载，不在请求过程中直接反序列化旧 pickle 或 MAT 文件。

模型不可用时保留旧规则作为兼容回退，并在响应中给出 `model_status=fallback` 和原因。旧阶段一产物记录的独立测试指标为 `R²=-0.38868`、`MAE=0.02074`，说明它可以复现原系统结果，但仍需更多独立数据验证泛化能力。

## 5.3 节点几何

五节苗节点通过无量纲比例重建。外侧斜杆比例 `alpha` 由净跨 Ridge Pilot 预测，内侧平杆比例 `beta` 由净跨与矢跨比 Ridge Pilot 预测；随后按中心对称知识约束重建 `Q1—Q4`。构件长度不是额外机器学习目标，而是由净跨、矢高和节点坐标确定性计算。模型仍标记 `pilot_not_for_production`，缺失或越界时采用固定回退值。

## 5.4 安全筛选指标

安全接口基于方案参数和规则结果计算平均可靠度代理、构件指标与评分，并附带腐朽风险提示。指标没有接入完整荷载组合、材料离散性、连接刚度、缺陷检测或有限元结果，不应写入正式鉴定结论。

## 5.5 Weibull–Gamma 寿命模型

寿命模型设条件寿命服从 Weibull 分布，风险率参数服从 Gamma 先验。两者组合后可解析得到生存函数和分位数，无需在线执行 MCMC。对于已服役年限 `c`，使用右删失条件 `T>c` 更新条件生存概率。

模型 V1 明确区分：

- `prior_predictive`：没有服役年限证据时的先验预测；
- `right_censored_update`：使用当前在役年限更新后的预测；
- `posterior_updated`：是否发生了证据更新；
- `missing_factors`：尚缺的树种学信息、气候湿度、腐朽深度和终点阈值等。

跨度、桥宽和矢高当前不会被错误地用作腐朽寿命依据。

## 5.6 候选方案评分

优化模块对每个候选执行同一参数模型与几何链，并按安全 40%、经济性 25%、拱形质量 20%、冗余度 15% 形成综合分值。当前权重和指标是系统内置的方案筛选规则，正式项目可在甲方确认评价口径后再标定。

## 5.7 数据质量控制

节点数据处理保留原始左右观测，以便检查历史结构不对称；训练目标使用左右均值形成对称几何输出。训练/验证必须以 `split_group_key` 分组，禁止同一桥或同一测绘谱系出现在不同数据折中。当前 103 条完成预处理，102 条、96 个隔离分组用于标准桥型训练；v6 的独立内部留出桥级宏 MAE 为 `alpha=0.09333`、`beta=0.02991`，但留出仍来自同一网站数据源，不属于外部验证。

# 6 系统使用说明

## 6.1 使用前准备

1. 使用甲方分配的系统地址和账号登录。
2. 建议使用当前主流版本的 Chrome 或 Edge。
3. 确认账号已获得桥梁设计相关菜单权限。
4. 如需三维模型，确认部署环境已完成 BIMFACE 配置。
5. 如需下载成果，确认浏览器允许文件下载。

## 6.2 快速完成一个方案

1. 进入“木拱廊桥智能设计”工作台。
2. 在 3D/对话区域输入设计描述，或直接打开“设计参数”。
3. 检查总长、净跨、桥宽、孔数、n1、n2 和矢高。
4. 点击预测或重新计算，进入“预测结果”查看建议。
5. 进入“结构图纸”，等待图纸生成并检查标题参数。
6. 需要时下载 PNG 图纸或从结果页导出 Excel。
7. 进入“安全分析”，补充服役和养护场景后执行筛选。
8. 进入“优化设计”，比较候选方案；选择方案后回到结果和图纸复核。

## 6.3 使用自然语言生成方案

输入时建议明确写出单位和字段名称。例如：

> 总长 42 米，单孔净跨 14 米，桥宽 4.5 米，3 孔，三节苗 8 根，五节苗 7 根，矢高 2.6 米。

提交后按以下顺序复核：

1. 孔数与总长是否一致；
2. 净跨是否被正确识别；
3. 桥宽和矢高单位是否为米；
4. n1、n2 是否符合方案意图；
5. 未在文字中提供的字段是否需要修改默认值。

## 6.4 手工调整参数

进入“设计参数”后直接修改字段。超出范围的值会被控件或服务端归一化。修改后必须重新预测；旧图纸和旧分析结果不应作为新参数的结果使用。

如只改变寿命场景（当前年限、暴露、维护、防腐），重新执行安全分析即可；如改变桥梁几何，建议依次重新执行预测、图纸、安全分析和优化。

## 6.5 查看和下载图纸

1. 打开“结构图纸”。
2. 若当前已有预测结果，系统会自动请求图纸。
3. 用缩放按钮或滚轮检查节点与标题栏。
4. 点击 1:1 恢复原比例。
5. 点击下载保存 PNG。

若图纸与参数不一致，先回到参数页重新预测，再重新生成图纸。

## 6.6 查看结果和导出 Excel

结果页按构件类型给出直径区间和长度估算。导出前确认页面显示的参数是当前方案，然后点击 Excel 导出。导出文件包含方案参数和设计结果，可用于后续整理，但仍需专业人员审查。

## 6.7 执行安全与寿命筛选

1. 选择木材类型；系统中的中文名称为俗名，不代表已确认植物学种和材性等级。
2. 填写当前服役年限；新建方案可填 0。
3. 选择暴露环境、维护水平和防腐处理状态。
4. 点击分析。
5. 先看模型状态和置信说明，再看寿命中位数与 90% 预测区间。
6. 检查“缺失因素”，不要只引用单一寿命数值。

对既有桥梁，若缺少检测和巡检数据，系统结果不能代替现场鉴定。

## 6.8 比较并应用候选方案

1. 在“优化设计”中生成候选方案。
2. 比较候选相对原方案的 n1、n2、矢高、平均直径和各评分变化。
3. 选择候选后点击应用。
4. 回到参数页检查回填值。
5. 重新生成结果、图纸和分析。

候选排名只反映当前内置权重。若项目重点不是默认权重，应由项目组先确认评价规则。

## 6.9 查看三维模型

进入“3D 模型”后等待模型加载。点击构件可查看属性。若提示 View Token、文件转换或网络错误，请联系运维检查 BIMFACE 环境配置；无需因此修改桥梁参数。

## 6.10 常见问题

| 现象 | 建议处理 |
|---|---|
| 自然语言识别的参数不准确 | 使用完整字段名与单位，提交后在设计参数页手工修正 |
| 图纸未显示 | 先确认已有预测结果，再进入图纸页；检查算法服务健康状态 |
| 菜单高亮与页面不一致 | 刷新后重新进入对应菜单；当前版本已实现路由与页签同步 |
| Excel 未下载 | 检查浏览器下载权限和算法服务连接 |
| 3D 模型无法加载 | 检查 BIMFACE 凭据、文件编号、文件转换状态和外网连接 |
| 寿命区间较宽 | 当前先验尚未用项目数据标定；补充长期巡检、材性、湿度和腐朽数据后再更新模型 |
| 优化方案分数高但不符合工程要求 | 当前为启发式筛选；按工程约束人工复核，必要时调整评价规则 |

# 7 部署与运行说明

## 7.1 环境要求

建议部署环境具备 Docker 与 Docker Compose。容器镜像构建需要 Node.js 和 Python 基础镜像访问能力；运行期需要可用的 PostgreSQL、持久化磁盘和反向代理端口。BIMFACE 为可选外部依赖。

## 7.2 配置原则

部署前应通过环境文件或平台密钥管理设置：

- Django 调试开关、允许主机和跨域来源；
- PostgreSQL 引擎、地址、端口、数据库、用户和密码；
- Redis 密码；
- 登录验证码策略；
- BIMFACE 应用密钥和文件编号；
- 图纸中文字体路径（非 Windows/Linux 默认字体环境需要配置）。

环境文件不得纳入公开交付包或版本库。实际地址、账号和密钥应由甲方运维体系管理。

## 7.3 Docker 启动

在项目根目录准备好部署环境变量后执行：

```powershell
docker compose -f docker-compose.bridge.yml up -d --build
```

查看状态：

```powershell
docker compose -f docker-compose.bridge.yml ps
```

查看某个服务日志：

```powershell
docker compose -f docker-compose.bridge.yml logs --tail 200 bridge-algorithm
```

停止服务：

```powershell
docker compose -f docker-compose.bridge.yml down
```

执行停止命令前，应确认没有正在进行的用户操作；数据库和媒体文件的备份策略由部署方案另行确定。

## 7.4 本地研发启动

本地研发可分别启动三个应用：

```powershell
# 算法服务
python -m uvicorn bridge_algorithm_service.main:app --host 127.0.0.1 --port 8001

# Django 服务（在 backend 目录或按项目文档执行）
python manage.py runserver 127.0.0.1:8002

# 前端服务（在 web 目录）
npm run dev -- --host 127.0.0.1 --port 8080
```

本地依赖安装、数据库迁移和前端环境变量应遵循项目 `Documentation.md`。生产环境不使用前端开发服务器。

## 7.5 健康检查

| 检查项 | 方法 | 正常结果 |
|---|---|---|
| 算法服务 | 请求 `/bridge-api/health` 或直连 `/health` | `{"status":"ok"}` |
| 前端 | 打开系统地址 | 登录页或已授权首页可正常显示 |
| Django | 执行 `python manage.py check` | `System check identified no issues` |
| 数据库 | 登录并读取菜单/基础数据 | 页面无数据库连接错误 |
| 图纸 | 创建方案后进入图纸页 | PNG 正常显示且参数一致 |
| BIMFACE | 进入 3D 模型 | 模型可加载；构件属性完整性按正式 BIM 数据另行验收 |

## 7.6 运行日志与问题定位

排查顺序建议为：浏览器网络请求 → Nginx 代理 → Django/算法服务日志 → 数据库或外部平台。算法接口问题应记录请求参数、HTTP 状态码和响应内容，但不得在工单中粘贴密码或平台密钥。

# 9 已知边界与后续事项

## 9.1 当前能力边界

1. 在线预测已恢复 SSA-XGBoost 与 CF-BPNN，但旧阶段一模型的独立测试 `R²` 为负，且原 SSA 搜索过程的精确版本仍需结合导师训练记录确认；不能把“已接入”写成“已充分验证”。
2. 节点几何 v6 Pilot 使用 102 条标准桥型记录和 96 个隔离分组，已接入本地受控服务，但尚未完成独立外部验证和专家双标，生产 Compose 默认不启用。
3. 安全分析是代理指标和风险提示，没有完成法定结构鉴定所需的检测与验算链路。
4. 寿命模型的先验、情景因子和腐朽终点阈值仍待项目数据标定。
5. 自然语言入口使用确定性规则，对含糊语句和复杂上下文的理解能力有限。
6. 优化模块使用预设候选和权重，不保证满足全部工程约束或得到全局最优解。
7. BIMFACE 能力依赖外部平台配置和网络。
8. 正式数据库、部署地址、组织账号、备份恢复、监控告警和验收数据需要目标环境确认。

## 9.2 建议后续工作

按交付优先级建议：

1. 与甲方确认交付名称、用户角色、部署地址、账号初始化和验收用例。
2. 在目标环境完成数据库、Redis、Nginx、字体和 BIMFACE 联调。
3. 建立一套经专家确认的标准输入/输出样例，作为回归和验收基线。
4. 收集可授权的真实节点标注和巡检数据，完成双人复核、外部验证和寿命先验标定。
5. 在正式账号下完成模型版本、`alpha/beta`、预测区间、回退原因和图纸跳转的浏览器验收，并把本源稿同步到下一版精排 Word。
6. 另行开展安全、权限、日志、备份恢复和生产加固专项；本报告按当前任务要求不展开安全审查。
